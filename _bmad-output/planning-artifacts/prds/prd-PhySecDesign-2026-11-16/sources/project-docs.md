## Product intent and recorded design decisions

- Site Studio is an interactive physical-security planning POC: import and geographically align drawings, place equipment, route cables, and derive a property-wide equipment schedule and illustrative materials estimate. A persistent geographic map underlies independent building/floor designs (site-studio/README.md:3–5; site-studio/POC-ROADMAP.md:5–12).
- Preserve the white/teal map-first design. Plans overlay map tiles; devices use geographic coordinates. Plan movement, rotation, uniform scale, opacity and locking, plus device placement, should remain directly accessible. OpenStreetMap works without a key; official Google Maps is optional with configuration (site-studio/AGENTS.md:13–18).
- Address lookup and aerial imagery help locate properties and align drawings to visible footprints. Changing map styles must not move plans or devices. Two-point alignment must preview translation, rotation and uniform scale, preserve aspect ratio and device coordinates, permit cancellation and undo (site-studio/AGENTS.md:18–20).
- PDF processing stays local, includes page preview/selection and identity, and feeds the satellite/two-point alignment workflow (site-studio/AGENTS.md:22).
- The original ordered POC scope is building/floor ownership and browser saving → generic equipment/schedule → same-floor cable routing → illustrative BOM/CSV. Independent floor content and v1 migration are deliberate commitments. Production hosting, live vendor catalogs and certified engineering calculations are excluded (site-studio/AGENTS.md:24).
- Coverage is sampled 2.5D geometry on a horizontal target plane. Lens/FOV link through sensor size; camera height/tilt and opaque barrier height affect visibility. Show assumptions and actual sampling resolution. Single-camera visible/blocked/near-blind meanings remain distinct from combined camera counts (site-studio/AGENTS.md:26–34).
- Combined coverage considers all active-floor cameras, regardless of display-layer visibility, and enabled barriers. Red=0 cameras, teal=1, purple=2+. Use the entire analysis area as the denominator, including solid footprints; overlap is a subset of Covered. Default extent is the whole uploaded image, not recognized building interior; allow custom polygon bounds. Each floor has a common target height, default 0 m, with visible warnings for invalid/excluded cameras (site-studio/AGENTS.md:28–34).
- Optional DORI uses IEC 62676-4:2014 thresholds and persistent horizontal stream resolution. Combined DORI takes the best level from one unobstructed camera at each sample; visible below-Detect samples stay distinct from unseen. Named zones have independent polygons/type and optional DORI requirements, measured across the entire zone; results should stay visible while adjusting cameras (site-studio/AGENTS.md:36–38).
- Survey notes/photos stay local, belong to a floor and link to a device or map point; deleting a device preserves its records as pins at the last location. Capacity uses editable bitrate, recording percentage, retention, endpoint ports, switch uplink ends and PoE allocations, with unassigned demand separately visible (site-studio/AGENTS.md:40–42).
- Project edits should be undoable during the session. Named revisions capture the complete local design, travel in backups, compare floors at the same scale and restore without destroying saved versions. Reviews attach to immutable named revisions using separate revocable reviewer bearer links, floor-pin comments and timestamped decisions; owner keys remain outside portable files and review data outside static routes (site-studio/AGENTS.md:44–46).

These are recorded project directions. The digest does not infer new users, business priorities, acceptance targets or production commitments from them.

## Claimed implemented capabilities to retain in discovery

### Map, plan import and alignment

- OpenStreetMap/Leaflet street view and no-key U.S. USGS aerial imagery, including dynamic NAIP Plus at close zoom; optional official Google street/satellite engine with a session browser key excluded from exports. View/style changes preserve coordinates. Explicit Photon address/place submission supports selectable results, coordinate parsing, cancellation, a 10-second timeout and bounded cache (site-studio/README.md:21–24,172–179; site-studio/design-qa.md:61–67).
- Image overlays accept PNG, JPG and WebP; PDF import offers one selected sheet per floor. Center/corner manipulation, numeric coordinates/width/rotation, opacity, 50% and hide-plan comparisons, relocation to search/map center, and alignment locking are described. Moving/realigning the drawing leaves geographic devices and barriers in place (site-studio/README.md:23–24,109; site-studio/design-qa.md:66–67).
- Two-point workflow picks drawing anchors and corresponding building anchors, previews then applies a similarity transform. Back, Start over, Cancel/Escape and alignment-specific undo are described. It shares Web Mercator geometry between rendering/picking/solving; preserves precise values when rounded inputs are untouched; rejects close anchors/unreasonable dimensions (site-studio/README.md:145–156).
- PDF limit 50 MB; local bundled PDF.js, local password prompt, page labels, thumbnails/direct page selection, bounded raster up to 3200 px longest side, aspect preservation, and embedded selected-image/source-page metadata. The source PDF and password are not exported. A fictional three-sheet sample is available; cancel preserves the prior overlay. QA also records six-thumbnail batches, nine-page pagination, protected/invalid-file handling and cancellation cleanup (site-studio/README.md:160–168; site-studio/design-qa.md:141–170).
- Device placement, selection/editing/dragging, camera bearing/FOV and layer visibility; a two-point distance measure; compact Project & layers/Properties toggles and direct plan import are recorded (site-studio/README.md:25,34; site-studio/design-qa.md:19,30–40).

### Project ownership, local persistence and portability

- Multiple buildings/floors; new buildings start with a blank ground floor and additional floors start blank. Each floor owns its drawing/alignment, devices, routes and barriers. Manage supports project/building/floor rename, addition and floor removal with content-count confirmation; the final floor cannot be removed. Active floor changes the design while schedules/materials aggregate the property (site-studio/README.md:21,36–38).
- One browser-current draft in IndexedDB with saving/saved/failed status. Portable v2 JSON embeds images, floor data, device/camera geometry and resolution, PDF page identity, routes/barriers, custom coverage bounds/target height, costs/accessories/labor and labor inclusion. Other sections also claim zone, survey/photo, capacity and revision persistence. Supported v1 files migrate to a building/floor; earlier v2 records gain compatible defaults (site-studio/README.md:28,40–42,48,62,70,87,141; site-studio/POC-ROADMAP.md:42–57).
- Opening a project replaces the current draft. Keys/transient interface state are excluded. Browser/profile/origin/site-data changes can make a draft unavailable; export is the portable backup (site-studio/README.md:40–42).

### Equipment, connections and estimates

- Nine generic items across eight types: cameras (dome and outdoor bullet), credential readers, lights, door contacts, intrusion sensors, intercoms, network switches and equipment cabinets. Devices have IDs, editable names/model/mounting details/notes/design intent and proposed/existing status. Searchable/filterable property-wide schedule includes building/floor/status and Locate returns to the correct floor/device (site-studio/README.md:25,83; site-studio/POC-ROADMAP.md:10).
- Same-floor routes connect different devices with direct paths or editable waypoints, Cat6/fiber/security cable categories, editable endpoints/type/slack, horizontal distance and 0–100% slack. Endpoints follow device movement; deleting a device removes its routes (site-studio/README.md:26,85; site-studio/POC-ROADMAP.md:11).
- BOM groups proposed devices by catalog item and cable by type across all floors, includes cable slack, and counts existing equipment separately. Persisted editable USD allowances, manual accessory and labor lines, equipment/cable/accessory/labor subtotals, optional installed-pricing labor inclusion and CSV of included estimate lines are described (site-studio/README.md:27,87; site-studio/POC-ROADMAP.md:12,34,55).

### Visibility, DORI and security zones

- Selected-camera rectilinear frustum on a target plane; linked focal length/HFOV, sensor width/aspect ratio, mounting height, downward tilt, bearing and analysis distance. Wall polylines and solid polygons have editable heights, enabled blocking and draggable vertices. Finite-height sight lines yield green visible, red blocked and amber conservative centerline near-blind regions; single-camera percentages use its sampled target-plane view (site-studio/README.md:93–111; site-studio/design-qa.md:221–246).
- Combined view evaluates the active floor's entire boundary with all floor cameras and enabled barriers. Common target height 0–10 m defaults to 0 m, independently of per-camera settings; invalid geometry/cameras at or below plane are excluded with warnings. Plan image bounds, camera surroundings or empty-floor map area provide defaults; custom simple polygon drawing/edit/redraw/reset/Fit area persists per floor. Covered/overlap/blind metrics use the whole sampled area, and overlap is not double-counted (site-studio/README.md:123–143).
- DORI option in individual and combined views saves stream resolution; documented defaults are 2688 px generic and 3840 px for the 8 MP bullet. The source claims thresholds 25/63/125/250 px/m, projected-scene-width density, visible-below-Detect distinction, mutually exclusive best-single-camera combined levels and Detect-or-better aggregation (site-studio/README.md:115–121). These are source claims, not independently researched standards in this extraction.
- Named editable floor polygons support entrance/parking/perimeter/restricted areas, type, optional minimum DORI level and required percentage. Zones show qualifying percentage/gaps at the floor common plane while cameras are selected/adjusted; save/export with the floor (site-studio/AGENTS.md:38; site-studio/POC-ROADMAP.md:42,48–49).

### Survey, outputs, capacity, history and reviews

- Survey pin or device note creation/editing, title, installation notes, labeled measurements/units and up to six JPG/PNG/WebP photos per note; images resized locally and embedded in saves/exports. Notes open from floor list/pin/inspector and follow devices, becoming last-location pins on removal (site-studio/README.md:44–48).
- Local printable PDF design packet for current/all floors, Letter/A4 landscape, coverage/combined-DORI/no-coverage selection, preview/page selector/download. Annotated drawings include north arrow/scale bar, equipment/cable schedules, zone requirements and survey measurements/optional photos. No-drawing floors use schematics; no live map tiles; 216 dpi pages. Editable project JSON and materials CSV remain available (site-studio/README.md:50–54; site-studio/POC-ROADMAP.md:51).
- Capacity inputs: project retention days; per-camera average bitrate, recorded percentage and switch-side PoE allocation. Estimates show decimal GB/TB storage and simultaneous stream bandwidth. Switch checks compare assigned copper/powered ports and watts to editable port, total power and per-port limits. Cameras/IP intercoms default to endpoints; other IP devices can be enabled. One direct same-floor Cat6 switch connection assigns an endpoint; switch-switch Cat6 counts an uplink at each end. Missing/ambiguous assignments are flagged but count in totals (site-studio/README.md:56–62).
- Undo/redo controls and Ctrl/Cmd shortcuts preserve last 40 session project edits, including drawings, devices/connections, zones, surveys and estimates. Up to 20 named full-project revisions persist in IndexedDB/portable backups. Same-scale floor comparisons between revisions or draft identify device adds/removals/moves/property changes. Restore replaces the working layout and is undoable. Project limit is 100 MB including revision images/photos (site-studio/README.md:64–70).
- Start a review from an immutable named revision; invite named/email reviewers with distinct copied bearer links; floor selection, pinned comments, approve/request-changes decisions, designer access to current/past timestamped decisions. Revoke/replace links without deleting decision/comment history; new revisions require separate reviews. Local Vite dev/preview API uses private disk data and browser owner keys; static Sites packages and project files do not carry the service/owner keys; snapshot limit 64 MB (site-studio/README.md:72–79).

## Deliberate limitations and unresolved planning work

- POC and generic estimates, not certified engineering, manufacturer suitability/procurement validation or PSP compliance. Drawings are fictional sample data over real geography; aerial roof outlines are not surveyed control (site-studio/README.md:83,172,188–192; site-studio/POC-ROADMAP.md:28–38).
- No native CAD, PDF editing/cropping, several simultaneous plans per floor, skew/perspective rectification or validation of inaccurate drawings. One selected raster sheet per floor; source PDF not retained in exports (site-studio/README.md:154–164).
- Local draft is neither an account nor cloud backup/sync. Local review links permit their bearer to act as the named reviewer; hosted identity/access/deployment remain future work. Static Sites delivery lacks the local review API. Cross-device reviewers require a reachable host address (site-studio/README.md:40,74–79,192).
- Google live credential testing is outstanding. Production map/geocoding provision is unresolved; public Photon has no uptime guarantee and no-key imagery is intended for U.S. sites with variable age/detail. Bundle splitting/production scale remain work (site-studio/README.md:172–179,192; site-studio/design-qa.md:45,92–95,281–285).
- Horizontal same-floor cable lengths do not engineer risers, vertical runs, physical routing obstacles/cable limits or installation allowances. Tax/freight are separate. Capacity is editable estimation: RAID/recorder overhead, peaks and undrawn uplinks require separate allowance (site-studio/README.md:62,85–87; site-studio/POC-ROADMAP.md:33–34).
- Walls/obstacles are manually traced; geometry does not add barriers to BOM or reroute cables. No lighting, image-quality guarantee, fisheye/lens distortion, glass transparency, terrain/full 3D, detection/identification certification. Sampling can miss narrow gaps; solid footprints and image margins count in coverage denominators. Individual amber area is a conservative centerline approximation (site-studio/README.md:93–111,119–121,129–143; site-studio/design-qa.md:245–247).
- Explicit remaining feature backlog: fence lines and entrance markers; gates and expanded model/mount/accessory options; network closet and port assignments; riser/vertical allowances; hosted collaboration identity/deployment (site-studio/POC-ROADMAP.md:44–57). Existing direct-switch inference/capacity does not establish explicit port assignment or a closet model.
- Licensed PSP reference material has not been supplied in these inputs. The roadmap links an ASIS PSP Body of Knowledge as a future discovery organizer across assessment/design/implementation and calls for verified reference → affected workflow → acceptance-check traceability; that linked material was not read in this digest. No licensed requirements, compliance baseline, authoritative requirement mapping or PSP acceptance checks are established by these four documents (site-studio/POC-ROADMAP.md:35,38,59; site-studio/README.md:192; site-studio/design-qa.md:52).
- The sources do not establish target customer/persona roles beyond designer/reviewer terminology, primary commercial outcome, measurable success thresholds, priority of production features, production-scale limits, release criteria or hosting/service procurement decisions. These are guided discovery gaps, not license to choose answers.
