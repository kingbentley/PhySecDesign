## Current analysis and status limits

- **Synchronous UI work:** App.jsx:127–149 runs single-camera, the selected targeted zone and combined analysis in React memo calculations. The combined calculation is suppressed while an active zone is selected. There is no demonstrated asynchronous all-zone recomputation, progress scheduling or stale-result generation guard. Thus fast control feedback and full-plan/all-zone completion are separate new implementation/measurement work.
- **Sampling:** UI requests0.75 m with6,000 single-camera and10,000 combined/selected-zone cells. Solver maxCells clamps at20,000 and automatically raises spacing under area/work limits (coverage.js:390–404, :657–665). Neither the requested spacing nor smooth contours establishes actual fidelity.
- **Work bounds:** single-camera edge budget1.5 million; combined camera-plus-edge budget2 million; prepared camera/edge combinations100,000; at most500 input camera records,100 barriers and100 vertices per barrier/boundary. Multi-head IDs and actual views are not implemented by this original one-record-per-camera solver. These bounds prevent some excessive work; they are not millisecond/response guarantees.
- **Illustrative larger case:**60 eligible views with100 relevant edges each imply60×101=6,060 work units/cell. The current2-million budget permits only330 cells. Across100×100 m this is roughly5.5 m spacing after grid rounding, rather than10,000 cells at1 m. This is a conditional example, not the declared real site's actual geometry. Adding all zones can require further calculations. A10-second limit alone cannot remove the solver's deliberate coarsening; engineering changes or an explicit accepted scope/target revision are needed.
- **Area integration:** coverage.js:707–726 clips cell area to the zone but assigns the entire clipped piece one class based on a sample point. Exact polygon-area clipping therefore does not make visibility/DORI-qualified area exact. Thin gaps, small zones, narrow shadows and threshold curves can need substantially finer than1 m. Contours do not change sampled totals.
- **Current target classification:** securityZones.js:15–28 compares unformatted percent with target using a1e-8 numerical epsilon; formatting rounds to one decimal (:32–34). ZoneInspector.jsx:19–21 displays Target met/Below target without a numerical-uncertainty/borderline state. It separately displays sampling and warnings (:77–83), but no asynchronous Updating/Previous result state is established. The tiny floating-point epsilon is not a2-point uncertainty allowance.
- **Unsupported input semantics:** current no-eligible-camera behavior reports the entire area uncovered (coverage.js:636–644). Accepted FR-13/48 now require unassessed/incomplete treatment when relevant panoramic outputs are unsupported, not proof of actual site blindness. Unsupported views get no DORI credit; this new distinction must survive pending/error handling and exports.

For future asynchronous processing, recommend explicit analysis freshness: mark Updating and any retained overlay Previous result; identify current/proposed basis and input version, do not let an older computation replace a newer one, and withhold a current Target met label until that result completes for the applicable inputs. A timeout or incomplete computation cannot become an empty/no-camera success. These are proposed observable safeguards, not a prescription for workers, servers or other architecture.

## Accuracy targets and boundary decisions

**Supported rectilinear FoV and DORI distance ≤1%:** reasonable as a proposed scalar software-fixture tolerance against independent analytic calculations, not a camera/manufacturer/field-accuracy claim. Define the quantity and coordinate frame: angular FoV, optical-depth threshold distance and ground-plane intersection distance are different. Current HFOV uses2 atan(sensorWidth/(2 focalLength)); projected pixel density uses imageWidth/(2 tan(HFOV/2) × opticalDepth), where tilt/height affect optical depth (coverage.js:20–27, :288–292). Test coherent source/profile inputs, known resolution and the existing DORI thresholds separately from sampled contour locations. Do not construct the reference by calling the production helper being tested. Exclude ill-conditioned near-horizon/singular cases from this relative-error metric only with explicit applicability and separate safe/invalid/limit behavior tests; use a declared absolute tolerance when a reference is zero or near zero.

**Zone qualification ≤2 percentage points:** use qualifying-area percentage, not2% relative error and not an unspecified absolute area. Compare the complete zone denominator to independent analytic or demonstrably converged reference integration. Use finer adaptive/locally refined sampling where required, and compare difficult small/narrow/concave/occluded cases. A grid of1 m is a maximum spacing for the proposed large timed fixture, not a universal accuracy guarantee. The implementation must meet both the relevant fidelity and timing conditions, or report the miss/revisit the candidate rather than silently coarsen.

**No false target success is stronger than a2-point error tolerance.** A reference89% and estimate90.5% at a90% target differ by1.5 points, satisfying the numerical tolerance while falsely reporting Target met. Using the full rather than rounded value prevents a display-rounding flip, but does not solve integration error. Conversely, this has no bearing on field Pass: modeled coverage must never manufacture a commissioning Pass at all.

Recommended distinction:

- Preserve the estimate, target, actual spacing, basis and relevant warnings. When the available numerical uncertainty/instability can cross the target, use an analysis label such as **Near target — refine analysis** or **Target not confidently demonstrated**. Do not add a fifth field-test outcome.
- Refine/independently check near-target cases before giving a confident modeled Target met/Below target classification. If a validated error interval exists, classify only when the interval is wholly on one side of the target; otherwise keep the boundary label. A2-point acceptance tolerance is **not** automatically a validated error interval for every arbitrary live design. A simple ±2-point review band may be a useful conservative UI trigger, but cannot by itself prove zero false success outside it.
- For test fixtures with known references, explicitly test both sides of the threshold, exact-boundary conventions and values that round alike. Never add the2-point tolerance to the user's target to turn a modeled shortfall into success. Do not let stale, unsupported or incomplete results receive target credit.

**Costs/units/counts:** independently check exact integer asset/interface/view/stream/run counts and the agreed grouping/rounding conventions. A multi-head device is one purchased body, its real interfaces/power count once, streams drive bandwidth/storage, and a run spanning several sheets counts once. Money must agree at the declared currency precision and stated line/subtotal rounding policy; unit conversions and cable/slack formulas use the same disclosed bases. This is precision against specified inputs, not a claim that estimated physical lengths or site demand are exact. Unknown inputs remain unknown, not zero.

## Recommendation for the next user-facing proposal

The250 ms/2 s/5 s/5 s/10 s candidates can be presented as prospective goals, with the10-second result explicitly covering the active plan's combined DORI and all its zones at the declared real-site view/geometry workload. Keep lightweight feedback, saving, final analysis and result freshness distinct. Pair the1%/2-point software tolerances with independent references, refinement when needed and a near-target analysis label. Do not promise a universal no-false-Target-met guarantee from sampled geometry or an unproved ±2-point bound. None of these candidate thresholds is measured or accepted by this extraction.

### Additional proposal boundaries from the parent

Optional initial-project readiness ≤10 seconds and in-project inventory lookup ≤1 second can remain separate unapproved targets. Define initial readiness with named required records/assets and cold/warm/network conditions; final DORI remains under its own completion target. Specify that inventory lookup means the600-device property's search/filter results; a one-second external address/geocoding guarantee is not supported by this proposal or current10-second provider timeout. File-processing/export/backup targets remain deferred until their input/output byte workloads are chosen.

Lock representative hardware/network, physical-device/view/stream counts, plan/zone/edge geometry, media and measured readiness conditions before running benchmarks. Retain outliers and failures; do not select easier camera orientations, fewer zones, warmer caches or reduced fidelity after seeing results to claim the declared workload passed. Unsupported/invalid or no-sample results must be labeled unassessed/unavailable as applicable, never evaluated as a successful zone result. The proposed near-target label requires bounded refinement and declared edge/reference fixtures; it does not require inventing a universally certified runtime error estimator.
