# Design and coverage — current-state source digest

Prepared 2026-11-16 for guided PRD discovery. This records implemented behavior and boundaries, not approved requirements or a proposed roadmap. Evidence is static source inspection; the referenced tests were located but not executed. No browser storage, private review data, or running user project was inspected.

## Maps, lookup, drawings and alignment

- The design canvas maintains a geographic basemap with a raster drawing overlay. Devices are latitude/longitude records, independent of drawing geometry. Leaflet renders the default map; optional Google Maps renders the same design through a separate map engine. Provider changes preserve the current viewport; source/style are not project data. Evidence: site-studio/src/MapCanvas.jsx:275, site-studio/src/MapCanvas.jsx:563, site-studio/src/MapCanvas.jsx:1012; site-studio/src/projectModel.js:123.
- Available sources are keyless OpenStreetMap street tiles, USGS aerial/satellite imagery described as U.S. coverage, and Google street/satellite using a user-entered Maps JavaScript API key. USGS combines overview tiles with a higher-resolution NAIP image requested for the visible extent at zoom 16 or above; network/load errors offer street-map fallback. Google key is held in session React state and explicitly excluded from portable project data. Evidence: site-studio/src/MapCanvas.jsx:81, site-studio/src/MapCanvas.jsx:284; site-studio/src/App.jsx:89, site-studio/src/App.jsx:525, site-studio/src/App.jsx:702, site-studio/src/App.jsx:817.
- Address/place search is explicit submit, not autocomplete. Default geocoder is Photon; VITE_GEOCODING_URL can replace it. It accepts 3–240 characters, returns up to five safe/deduplicated results, times out after 10 seconds, and caches 30 queries in memory. Latitude/longitude input is parsed locally without a geocoder call; supported map coordinates are latitude ±85°, longitude ±180°. Choosing a result moves the map only; a separate Bring plan here action moves an unlocked drawing and leaves devices in place. Evidence: site-studio/src/geocoding.js:1, site-studio/src/geocoding.js:16, site-studio/src/geocoding.js:68; site-studio/src/AddressSearch.jsx:17, site-studio/src/AddressSearch.jsx:51; site-studio/src/App.jsx:530.
- One drawing is stored per floor. Users import PDF (up to 50 MB) or PNG/JPG/WebP (up to 12 MB), including drag/drop. Replacing the drawing preserves that floor's device coordinates. Imported images start at map center with a 140 m width and proportional height; PDF placement also preserves page proportions and switches to satellite. Supported import is raster/image based; the UI directs CAD users to export PDF first. Evidence: site-studio/src/App.jsx:434, site-studio/src/App.jsx:456, site-studio/src/App.jsx:698, site-studio/src/App.jsx:815.
- PDF contents are parsed/rendered locally with PDF.js. The picker offers six-page thumbnail batches, direct page navigation, selected-page preview, password entry for protected files, cancellation and error recovery. Only the chosen page is rasterized into the floor overlay; stored source identity includes PDF name, page number/count/label, page dimensions and raster dimensions. Import raster maximum is 3,200 px and 10 million pixels, with a 2,400 px fallback when needed to remain below 12 MB. Original PDF bytes, text, vector/CAD objects and PDF password are not represented in the project schema. Evidence: site-studio/src/pdfImport.js:27, site-studio/src/pdfImport.js:75, site-studio/src/pdfImport.js:109; site-studio/src/pdfImportUtils.js:1; site-studio/src/PdfPagePicker.jsx:39, site-studio/src/PdfPagePicker.jsx:61, site-studio/src/PdfPagePicker.jsx:73; site-studio/src/projectModel.js:62.
- Drawing controls include map drag/resize, rotation, proportional width, opacity/visibility, coordinates, 1 m nudges, move-to-map-center, and alignment lock. Two-point alignment collects two image points then two geographic counterparts, previews the resulting translation/rotation/uniform scale, and supports back/restart/cancel/apply and an explicit last-alignment undo. It preserves aspect ratio and transforms only the drawing. Target anchors must be at least 0.5 m apart and within a 3 km baseline; resulting drawing is restricted to 5–1,000 m wide and 1–2,000 m high. - A two-click geographic ruler reports metres. This is a map distance, not drawing recognition or an automatic scale calibration. The demo drawing explicitly says it is fictional and not surveyed to its location. Evidence: site-studio/src/MapCanvas.jsx:327; site-studio/src/App.jsx:710, site-studio/src/App.jsx:806.

## Buildings, floors, catalog and cable routes

- Users can rename the project, add/rename buildings, add/rename/select floors, and remove floors while keeping at least one floor in the project. Adding a building also creates its blank ground floor. Each floor owns its drawing/alignment, devices, routes, barriers, zones, survey notes, analysis polygon and common target height. New floor center comes from the current map. The model has no building footprint, floor elevation or stacked 3D geometry. Evidence: site-studio/src/FloorManager.jsx:50, site-studio/src/FloorManager.jsx:100; site-studio/src/App.jsx:176; site-studio/src/projectModel.js:357.
- Catalog contains nine fixed generic choices across eight types: two camera presets, credential reader, exterior light, door contact, motion detector, IP intercom, PoE switch and cabinet. Users choose an item then place it on the active map; device settings include editable name/model, proposed/existing status, mounting text, design intent and installation notes. Search/type filter covers both catalog and a property-wide schedule, and Locate navigates to a device's floor. This is not a live manufacturer inventory; model/specification is free text. Evidence: site-studio/src/catalog.js:3, site-studio/src/catalog.js:21; site-studio/src/EquipmentPanel.jsx:13, site-studio/src/EquipmentPanel.jsx:24, site-studio/src/EquipmentPanel.jsx:47; site-studio/src/App.jsx:202, site-studio/src/App.jsx:786.
- Devices can be moved on the map, and their type layers shown/hidden. Each saved cable route connects two distinct devices on the same floor; supported types are Cat6, fiber and security cable. Users choose endpoints, click intermediate waypoints, save/edit/remove paths, drag saved bends, and set a 0–100% slack allowance (default 10%). Endpoints follow device positions. Deleting a device removes its connected routes. Evidence: site-studio/src/MapCanvas.jsx:374, site-studio/src/MapCanvas.jsx:633; site-studio/src/App.jsx:213, site-studio/src/App.jsx:225, site-studio/src/App.jsx:671; site-studio/src/RouteInspector.jsx:48; site-studio/src/projectModel.js:143.
- Route length is the sum of horizontal geographic segments, plus the selected slack for material quantity. Vertical runs and installation conditions are explicitly outside that estimate. The route model has no inter-floor riser or automatic obstacle-aware pathfinding. Evidence: site-studio/src/cables.js:15, site-studio/src/cables.js:33; site-studio/src/RouteInspector.jsx:109.

## Single-camera and combined coverage

- Coverage is a local POC 2.5D rectilinear camera intersected with a horizontal target plane, limited by an analysis range and opaque vertical barriers rising from floor level. It does not model terrain, lighting, fisheye/lens distortion, full 3D, real image quality or certification. Lens and horizontal FOV stay linked through sensor width; vertical FOV follows aspect ratio. Evidence: site-studio/src/coverage.js:1, site-studio/src/coverage.js:20, site-studio/src/coverage.js:253; site-studio/src/CameraControls.jsx:102, site-studio/src/CameraControls.jsx:127.
- Camera controls expose lens/FOV, mounting height (0.5–30 m), downward tilt (0–90°), bearing, target plane (0–10 m and strictly below lens), analysis distance (1–150 m), sensor width (1–36 mm), and preset/custom aspect ratio (0.5–4). Analysis distance is explicitly not a detection guarantee. Legacy cameras preserve prior FOV by deriving consistent optics. Evidence: site-studio/src/CameraControls.jsx:80, site-studio/src/CameraControls.jsx:104; site-studio/src/projectModel.js:97.
- Users trace wall polylines or simple closed solid obstruction polygons, name them, set height (0.1–50 m), toggle whether they block views, redraw/edit/remove them, and preview coverage while drafting. Geometry stays geographically anchored when the drawing moves. Model limit is 100 barriers per floor, each up to 100 points; walls need two points, obstacles three and a non-crossing area. Evidence: site-studio/src/App.jsx:239; site-studio/src/BarrierInspector.jsx:31; site-studio/src/projectModel.js:217.
- Single-camera display distinguishes visible, blocked and approximate near-blind regions, with nominal footprint outline. Visibility percentages use only the sampled nominal footprint on that camera's own target plane; the near-blind region is a centerline-based approximation. Warnings flag invalid geometry, camera inside/above an obstruction, empty footprint and coarse sampling. Evidence: site-studio/src/coverage.js:278, site-studio/src/coverage.js:359; site-studio/src/CameraControls.jsx:131; site-studio/src/MapCanvas.jsx:454.
- Combined coverage analyzes the entire active-floor boundary: red is unseen by any camera, teal seen by exactly one, purple by at least two. Covered is the union; overlap is already included in Covered. Solid obstruction footprints remain in the denominator. All floor cameras enter analysis irrespective of display-layer visibility. The common floor plane defaults to 0 m, overrides per-camera target planes for this view, and excludes/warns about invalid cameras or lenses at/below that plane. Evidence: site-studio/src/App.jsx:132; site-studio/src/coverage.js:557, site-studio/src/coverage.js:590, site-studio/src/coverage.js:738; site-studio/src/CombinedCoveragePanel.jsx:55; site-studio/src/MapCanvas.jsx:433.
- Default analysis bounds are the rotated drawing image extent, else a box around cameras/ranges with 2 m margin, else the stored blank-plan area. The image extent includes sheet margins; it does not identify building interiors. Users can draw a simple polygon (3–100 vertices), edit corners, fit it on map, redraw or restore defaults. Concave boundaries are supported; holes/multiple boundary polygons are not in the model. Area extent must be below 20 km across. Evidence: site-studio/src/coverageArea.js:28; site-studio/src/CombinedCoveragePanel.jsx:77; site-studio/src/projectModel.js:238; site-studio/src/coverage.js:509.
- Computation is sampled despite its vector-looking overlays. The app requests 0.75 m cells with 6,000 single-camera/10,000 combined-cell budgets; the solver increases spacing under area/edge workload. Actual resolution and warnings are visible, but no user sampling-resolution control is wired. Combined analysis accepts at most 500 cameras, less than the project's 5,000-device per-floor storage limit. Display contours refine boundaries without changing sampled totals, and both Leaflet and Google draw polygon collections. Small gaps/thin obstacles/narrow overlaps can be missed; smoother shapes do not imply exact area or optical accuracy. Evidence: site-studio/src/App.jsx:127, site-studio/src/App.jsx:137; site-studio/src/coverage.js:390, site-studio/src/coverage.js:574, site-studio/src/coverage.js:657; site-studio/src/coverageContours.js:1; site-studio/src/MapCanvas.jsx:419, site-studio/src/MapCanvas.jsx:801; site-studio/src/projectModel.js:366.

## DORI and security zones

- Optional DORI overlay applies the implemented IEC 62676-4:2014 thresholds of Detect 25, Observe 63, Recognize 125 and Identify 250 px/m. Visible Below Detect is distinct from Unseen/Blocked. Pixel-density estimate uses horizontal stream resolution (integer 160–16,384 px) and ideal optical depth; generic defaults are 2,688 px or 3,840 px. Combined DORI takes the best level from any single unobstructed camera at each point, not summed resolution from overlapping cameras. UI labels these estimates and calls for live-footage verification of face angle, lighting and compression. This digest records the implementation's standard attribution; it does not independently certify conformance. Evidence: site-studio/src/dori.js:1; site-studio/src/coverage.js:288, site-studio/src/coverage.js:674; site-studio/src/CameraControls.jsx:92; site-studio/src/DoriControls.jsx:25.
- Security zones are separate named floor polygons, independent of the overall analysis boundary. Types: entrance, restricted area, parking, perimeter area, other. Each can carry no requirement or a DORI level plus 0.1–100% required coverage (new-zone default 90%). Results measure the entire zone against that level or better, using all eligible floor cameras at the common floor target plane. UI displays percent, target met/below target and qualifying/gap fills; selecting/adjusting a camera retains zone results. Up to 100 zones per floor and 100 vertices per simple zone. Evidence: site-studio/src/securityZones.js:3, site-studio/src/securityZones.js:15; site-studio/src/App.jsx:137, site-studio/src/App.jsx:300, site-studio/src/App.jsx:782; site-studio/src/ZoneInspector.jsx:6, site-studio/src/ZoneInspector.jsx:75, site-studio/src/ZoneInspector.jsx:118; site-studio/src/projectModel.js:247.

## Persistence and discovery cautions

- One browser-local draft is saved in IndexedDB, after restoration, through serial normalized writes and a 350 ms debounce. Save failure is surfaced with an export-backup action. Portable v2 JSON embeds drawings and retains per-floor settings; v1 imports migrate to one building/floor. Source PDF identity survives, but only selected-page raster data is portable. Missing older-v2 coverage/zone fields receive compatible defaults. Evidence: site-studio/src/projectStorage.js:5, site-studio/src/projectStorage.js:45, site-studio/src/projectStorage.js:114; site-studio/src/projectModel.js:341, site-studio/src/projectModel.js:383, site-studio/src/projectModel.js:455; site-studio/src/App.jsx:500, site-studio/src/App.jsx:700.
- Persisted design settings include drawing transform/opacity/lock, camera optics/resolution, equipment metadata/status, route/slack, barriers, custom analysis bounds, common target height and security zones. React-only view settings (provider/style/key, type-layer visibility, selected camera, single/combined mode, DORI on/off, panel selections) are not portable project fields.
