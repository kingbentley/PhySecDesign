## POC boundaries the draft must state accurately

- **Planning fidelity:** sampled 2.5D rectilinear cameras, flat target planes and opaque vertical barriers; no full 3D/terrain, lighting, fisheye/distortion, real image quality, guaranteed detection or certified engineering. DORI standard attribution records the implementation's chosen thresholds; it is not independent compliance verification. Near-blind shading is approximate; smooth contours do not remove sampling error. Zone Target met is not field acceptance.
- **Spatial scope:** manually aligned one-sheet raster overlays, no native CAD/PDF editing, automatic interior recognition, perspective/skew correction, building footprints/floor elevation, inter-floor risers or obstacle-aware cable routing. Cable estimates remain horizontal plus slack.
- **Estimates:** generic manually editable allowances, not live vendor models/prices or procurement validation. Accessories/labor are manual; tax/freight separate. Capacity excludes RAID/recorder overhead, peak traffic, throughput/topology and undrawn uplinks; direct-switch inference is not explicit closet/port assignment.
- **Current persistence/collaboration:** one browser/profile/origin draft is not a project directory, cloud account, sync or reliable backup. The Projects control is static. Review is an asynchronous local-server feature, absent from static Sites hosting. Bearer possession is attribution rather than verified identity. Project backups do not restore review rooms/history or owner access.
- **Reduced outputs:** PDF is static raster pages without live map tiles, searchable text/vector layers, capacity, BOM/cost or review decisions. Review snapshots are narrower still: layout and basic device identity, omitting survey/photos, equipment model/notes, detailed optics/coverage settings, capacity and costs. Neither currently delivers the newly requested complete lifecycle package.
- **Loss/limits:** survey photos are resized previews rather than original evidence archives; original PDFs are not retained. Current bounds include 100 MB portable projects including revision duplication, 64 MB review snapshots, 20 full revisions, six photos per survey note and 24 MB encoded photos per design. These are implementation limits, not accepted future scale/performance targets. A stored 5,000-device floor does not imply coverage supports 5,000 cameras (analysis caps at 500).
- **Verification:** recorded core/combined-coverage QA is historical. Later code/tests/screenshots do not establish fresh acceptance of DORI, zones, survey, reports, capacity, extended estimates, revisions or reviews. Google has no live-key acceptance evidence. The revision-comparison missing-icon import remains an unconfirmed static defect candidate. Stale README claims that undo is absent/core validation pending must not override newer source evidence.

## New requirements, not existing implementation

The decision log confirms an expanded POC: shared online designer/installer project with shared demo access; online phone/tablet/laptop field work; optional handoff and nonblocking project-assigned approvals; installation/configuration/testing with editable device-type checks, expected/actual results, Pass/Fail/Not tested/Not applicable, explanations, optional/project-required photos, actor/time and retained retests; preserved issued design versus direct logged field changes with affected calculations/tests flagged; explicit closeout states and visible outstanding work; searchable removed-device archives with retained history/removal data, active-calculation exclusion, restoration and linked replacement identity. These must be drafted as new requirements, not credited to the local draft/review/survey features. The continuing-property/new-work model was still marked proposed in the inspected decision log; incorporate any later user confirmation from the parent session.

Doors/gates and expanded equipment options, fence/entrance lines, explicit network closets/ports and vertical cable allowances remain backlog or unresolved scope in these sources. No licensed PSP documents, compliance baseline or complete standards traceability was supplied. Competitor reference capabilities inform context only and must not be automatically adopted. Offline capture/sync and individual sign-in/invitations are explicitly outside the currently confirmed POC; online sharing is now required despite the original local-only baseline.

## Five drafting traps

1. Do not let new commissioning work erase existing map/alignment, materials, capacity, DORI/zones, revision or export capabilities; conversely, do not freeze every numeric prototype limit as a requirement.
2. Keep full named revisions, reduced review snapshots, issued designs, field records and fixed closeout records distinct. Current approvals neither cover complete project data nor automatically apply to later changes.
3. Replace current destructive device deletion deliberately when implementing archive semantics: routes currently disappear and surveys become pins. Preserve the newly required device/connection/history record without counting removed devices as active or treating old tests as current proof.
4. Do not equate plausible planning geometry, a threshold label, optional approval, completed installation, passed tests and project closeout. They answer different questions; bypassing approval must not fabricate any other result.
5. Shared online POC access is new implementation scope, but it does not silently expand into production identity, live collaboration conflict handling, offline sync, certified engineering or vendor integration. Keep unresolved package/archival/access details visible rather than infer completion.
